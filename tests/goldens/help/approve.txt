usage: pulsar approve [-h] [--format MODE] [--json] [--account ACCOUNT] [--workspace DIR]
                      [--ttl TTL]
                      plan

approve a plan's exact content so an agent may publish it (a human, at a terminal)

positional arguments:
  plan               plan file (YAML)

options:
  -h, --help         show this help message and exit
  --format MODE      output: auto (a table on a terminal, tab-separated lines when piped), table
                     or json; default: $PULSAR_FORMAT, else auto
  --json             shorthand for --format json
  --account ACCOUNT  one of the plan's accounts, or the one to bind a plan that names none;
                     default: default_account in config.toml, else the only bound account
  --workspace DIR    resolve the plan's media against DIR and keep them inside it, as the Orbit
                     plugin does (the command the plugin prints passes it); default: the current
                     directory and the configured media roots
  --ttl TTL          how long the approval lasts: 90m, 72h, 7d (at most 30d); default: 72h for a
                     reply, 7d otherwise

Examples:
  pulsar approve engagement/2026-09-27/reply-1.yaml
  pulsar approve content/2026-10/launch/plan.yaml --ttl 3d
An edit to the plan changes its digest and needs a new approval; a new not_before does not.
